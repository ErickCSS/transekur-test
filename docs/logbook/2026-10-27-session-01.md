# Session 01 — 2026-10-27

## Goal
Understand the test, decide the architecture and get the screens ready to validate.

## Decisions
- One app with a three-option home ([0001](../decisions/0001-one-app-three-modules.md)).
- Supabase as the backend ([0002](../decisions/0002-supabase.md)).
- Simulated notice + WhatsApp link ([0003](../decisions/0003-simulated-notice-whatsapp-link.md)).
- Real login with Supabase Auth ([0004](../decisions/0004-driver-login-supabase-auth.md)).
- Module conventions; the *service* entity is called `Trip` in code ([0005](../decisions/0005-module-conventions.md)).
- Design first with a mock database ([0006](../decisions/0006-design-first-with-mock-data.md)).
- UI in English.

## Done
- Installed `@supabase/supabase-js`, `@supabase/ssr` and `server-only`.
- `docs/` folder with index, ADRs, architecture, design and this logbook.
- Modules: `shared`, `home`, `dispatch`, `driver-auth`, `driver`, `client-notice`, `notifications`.
- Real login with Supabase Auth; 3 test accounts created with `scripts/seed-driver-accounts.mjs`.
- `proxy.ts` protects `/driver/services` and sends a signed-in driver away from the sign-in page.
- Mock database in `localStorage`, shared between tabs.
- Home, Dispatch, Driver (sign in + today's services) and Client (inbox + WhatsApp) screens.
- One-pager with the plan, assumptions and questions for the client.

## Problems found
- **`Date.now()` during prerender**: with `cacheComponents`, the Supabase client reads the clock while loading the session. Fix: `await connection()` in `createSupabaseServerClient` to force request time.
- **Dates in client components**: to avoid `new Date()` in the server render, the mock-database content mounted only on the client.

## Verified
- `pnpm lint`, `tsc` and `pnpm build` without errors.
- Browser flow: create a service in dispatch → Carlos signs in (mobile) and sees only his 3 services for today → "I'm 10 min away" → the client sees the message with name and vehicle + correct `wa.me` link → dispatch shows *Sent*.
- Sign out redirects to `/driver`, and `/driver/services` stays protected.
